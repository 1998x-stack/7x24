# V1.0 local workbench operational runbook

## Preflight

- Confirm that all upstream stacked changes are present in the chosen PR and that V1.0 targets main.
- Use `news24 doctor --json` to check a writable data folder and SQLite FTS5 trigram.
- Back up a live database through the SQLite backup API or VACUUM INTO while quiescent. Never copy only the main WAL db file during active writes.
- `news24 db migrate --db PATH` creates/upgrades schema to version 4. Migrations are additive; older binaries refuse higher schema versions.

## Start local web

Run `news24 web serve --db PATH --port 8765`, then open `http://127.0.0.1:8765`. The app binds 127.0.0.1 only. Static JS/CSS are packaged into the installed wheel. No CDN or browser cookies. The app is **read-only by default**.

For human reviews, set `NEWS24_REVIEW_TOKEN` (at least 16 characters; generate a high entropy value) and `NEWS24_REVIEWER` in the terminal environment before starting. Paste the token into the UI input to perform approved writes. Token stays in tab memory only. Browser requests require same Origin/Host; the secret is compared in constant time by the backend. Never save or expose the token via URL, files, Git commits or shell history.

A local token is NOT secure public authentication. Do not bind on a public interface or publish behind a reverse proxy without a dedicated reviewed identity/TLS/auth layer.

## Review semantics

- A source revision hash fences a claim review. Once a news item is corrected/deleted, a review against its old revision is rejected.
- Optimistic `expected_version` ensures two reviewers cannot silently replace each other. On conflict, reload latest and explicitly create another immutable version.
- `SUPPORTED_BY_TEXT` means a reviewer judged text support; it **does not prove the claim is true in the external world**.
- A claim with missing/ambiguous source quotation may never be marked `SUPPORTED_BY_TEXT`.
- Candidate event reviews record the operator's association assessment and never auto-merge the underlying article records.
- Logs are append-only; historical model responses and original source text are unchanged.

## Operational monitoring

Use `news24 jobs list`, `news24 health` and `news24 audit` for background state. Source and model APIs require authorized network tests; quality status explicitly says NOT_PRODUCTION_VERIFIED until additional external checks are done.

## Validation and recovery

```bash
make lint typecheck test smoke
news24 evaluate evidence --dataset tests/fixtures/intelligence/evidence_gold.json
python -m pip install -e '.[dev,browser]'
python -m playwright install chromium
pytest -q tests/e2e
```

Unit/integration/browser fixtures are synthetic and do not claim live upstream compatibility. If review writes fail, first check that the browser is on localhost, Origin is correct, token is configured, the analysis points at the latest article revision, and the review version is current.

## Future hardening before a production release

External API contract verification and golden real-source samples, real model regression and cost/rate limits, multi-user identity and network security review, accessibility screen-reader testing, streaming long-history backfills, human fact-check reliability benchmarks and separate data rights assessment are mandatory release gates.
